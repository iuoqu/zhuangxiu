# 办公空间产品推荐能力开发计划

状态：2026-10-15。只规划产品能力，不安排试用、客户测试或官网修改。目标是兑现官网所述拖拽布局、即时照片级可视化、自动真实家具清单、报价和下单。

**MVP 范围修订（10 月 17 日）**：真实目录继续暂缓，允许使用明确标记的版本化示范目录完成可展示闭环。示范数据可以进入演示选品、摆位复核、采购草案、演示报价和演示订单申请；任何界面与导出均不得把它描述为真实供应、正式报价、付款或供应商订单。

**范围修订（10 月 15 日）**：家具分类不能只按办公室的“工位/储物”功能来做。商品和设计需求均记录明确品类；首批覆盖衣橱、桌、椅子、梳妆台、沙发、茶几、矮柜和床，同时保留办公桌、会议桌、电话亭、柜、架等办公品类。当前编辑器可手动摆放上述八类示例家具，并在设计清单逐类计数；自动生成 A/B/C 的空间规划仍限现有办公室场景，家居空间的自动规划、净空规则和商品覆盖尚未完成，不能把“类别已建模”说成“家居产品已可交付”。

## 产品定义与第一批支持范围

输入已核对的办公场地和结构化需求，系统先生成家具功能与规格需求，再从持续更新的商品来源中寻找候选，选出能放进空间的组合，生成最多三套不同取向的布局。每套方案给出数量、位置、匹配到的 SKU、选择理由、未满足项和可替代品。编辑后重新计算检查与清单。可核价商品才计算确定金额。

当前自动方案首批只支持单层、尺寸明确的矩形办公室；门、窗、柱、禁占区、既有房间由人核对。办公功能需求包括工位桌、办公椅、会议桌、会议椅、电话亭及具体储物类型；功能角色与家具品类分别记录。需求字段为工位数、会议座位数、电话亭数、储物数量、预算、交期和开放/私密偏好。A/B/C 分别偏向容量、均衡、私密度。非矩形场地、未理解的需求明确显示为未覆盖；已识别但未找到可用商品的需求显示为“待选品”，不用示例产品冒充。

品类是商品匹配的硬条件：衣橱和矮柜、茶几和普通桌、梳妆台和办公桌不能因为长宽相近而相互推荐。角色进一步区分用途，例如同属“椅子”的办公椅、会议椅和普通椅。供应商只写“storage”但不说明是衣橱、矮柜、文件柜或架子的记录保持未分类，等待补充资料。设计清单按具体品类、角色、尺寸和场景实例分组；采购清单必须再次核对品类、来源、尺寸、采购单位与摆位结果。

“尽可能推荐”有边界：硬条件不成立就拒绝候选；偏好不满足可以保留候选但要说明代价。AI 可以把自然语言转成待核对需求，也可以从商品资料中发现、抽取和比较候选；不能凭空编造 SKU、尺寸、可售状态或金额。没有合格组合时输出具体缺口，不输出看起来完整却无法订购的图。

## 数据协议与推荐逻辑

| 对象 | 最少字段 | 规则 |
| --- | --- | --- |
| 场地 site | ID、版本、毫米边界、门/出口、柱、禁占区、核对状态 | 边界变化使旧方案过期 |
| 需求 brief | 版本、各功能数量/优先级、预算、交期、布局偏好 | 缺失值保持待补充，不虚构 |
| 功能需求 productSlot | 类别、数量、尺寸上限、使用净空、预算/交期偏好、必需或可替代 | 从布局与需求确定，不依赖先找到商品；是“要买什么”的设计清单 |
| 商品候选 productCandidate | 供应商、来源链接/文件、供应商 SKU、抓取时间、字段证据、长宽高、配置、报价/可售状态、验证状态 | AI 可抽取候选，但缺尺寸/来源的候选不得自动放入精确布局；外部商品信息可能过期 |
| 已核实商品 catalogItem | SKU、目录版本、可售状态、长宽高、使用净空、配置、组合部件、价格来源/更新时间、交期、2D/3D 资产 | 可来自持续导入的供应商目录；缺价不能生成确定金额；下单前复核供货与价格 |
| 布局 layout | ID、场地/需求/目录/规则版本、家具实例的功能位 ID、可空 SKU、配置/坐标/朝向、算法版本与种子 | 2D、3D、清单、报价共用这一版本；未匹配商品的实例保留功能位，不伪造 SKU |
| 推荐 recommendation | 硬检查、偏好评分、推荐理由、未满足项、替代 SKU 与拒绝原因 | 可解释为何选择或拒绝 |

双人工位等组合块可以在图上显示为一个对象，但采购清单必须展开真实桌椅 SKU 与数量。尺寸、颜色、饰面影响售价或供货时，配置代码必须可追溯。产品尚未核实时，图上保留功能占位和尺寸约束，设计清单保留需求数量；采购清单中的该项标“待选品”，不生成假 SKU 或假价格。

计算顺序：从场地与需求生成产品功能位 → 从供应商目录、商品文件及有明确来源的商品页检索候选 → AI 归一化名称、规格和替代关系 → 用已核实尺寸与净空生成摆位 → 排除越界、碰撞、堵门、侵占通道/禁区的候选 → 按满足数量、预算、交期和偏好评分 → 输出不同取向的 A/B/C → 从家具实例展开采购清单、计算可确定金额并生成展示。通道检查属于产品规划规则，不自动作建筑法规合规判断。

### 两层清单与 AI 的准确职责

1. **设计清单**由布局确定，列“12 张 1400 mm 左右工位桌、12 把办公椅、1 套六人会议桌椅”等功能、尺寸区间、数量和摆放位置。即使一个商品都没找到，这张清单也成立；数量由代码从场景实例计算。
2. **AI 选品**对每个功能位在连接的供应商目录、表格、商品资料中检索若干候选，抽取 SKU、尺寸、材质、配置、图片、价格、交期和来源；归一单位，识别“桌椅套装”与单品差异，并建议可替代品。每个字段保存原始证据和更新时间。AI 的相似度只负责召回与解释，不能覆盖硬尺寸、组合与供货检查。
3. **采购清单**只把已核实的候选绑定到布局实例，再按组合部件展开 SKU 和数量。自动核实可以来自受信的供应商数据源；网页发现的候选要经过资料核对或供应商确认。缺尺寸、缺来源、缺价格或供货未确认时，分别显示“不能精确摆放”“不能核价”“不能下单”，仍保留设计清单中的该项。
4. **持续补库**记录未匹配功能位及搜索词，按出现频次扩展供应商来源和商品类别；不追求一次收齐市场家具。每次报价/下单前按商品来源重新核对价格、供货和配置。商品变更生成新目录版本，旧方案与旧报价不静默变化。

由此可以对未知需求保持开放：先说明需要什么，再尽力找可买的候选，最后只把有证据的商品放进正式采购链。商品网页的结构化数据有时提供价格与可售状态，但不等于具备摆位所需的实物尺寸、使用净空或可采购承诺。

排序采用分层规则，避免“偏好分数高”掩盖必需功能的缺口：先保留硬检查通过的候选；再按必需数量缺口从少到多排序；其后考虑预算和交期；最后比较容量、空间利用和开放/私密偏好。A/B/C 用不同的最后一层权重选出，且布局或产品组合必须存在实际差异。同样的 SKU 若有更小规格能解决尺寸冲突，推荐该替代并说明原规格被拒原因。

### 可视化与交易的细化出口

即时视觉先用真实 GLB、产品材质、光照与阴影组成可交互的浏览器场景；高质量图片从同一场景版本生成。内部性能目标先设为：18 × 12 m、最多 100 个家具实例的标准样本，在项目指定的参考笔记本和浏览器中，移动或替换家具后 P95 不超过 2 秒看到更新后的真实材质视图。设计负责人对固定三个样本逐项核对空间、型号、颜色与主要物件数量。若视觉质量或时延未通过，不把当前基础三维或等待较久的导出图算作“即时照片级”。

报价至少包含商品明细、配置、数量、商品价、配送、安装、税费、有效期和无法确定的项目；状态为草稿、已核价、已确认、已转订单。订单引用已确认报价与方案版本，记录订单号、每项 SKU/数量、供货复核、配送/安装状态。修改商品、数量或场地使原报价失效并生成新版本；不可在旧报价上直接改数字。以上是实现官网“清单 → 报价 → 下单”所需的最小状态链，不预设支付方式。

## 商品数据先决条件

产品/采购负责人先指定可持续接入的供应商目录或商品文件来源，并确认哪些来源的尺寸、价格与供货字段可信。每个进入采购清单的商品须具备实物尺寸、使用净空、可选配置、组合部件、附件边界、当前可售状态、价格或询价规则、交期来源和 2D 轮廓；3D 资产单独决定能否精确展示，不能以缺 GLB 否定可采购性。工程按此建导入格式和校验。无需一次提交全部市场商品；没有核实商品的功能位可以保留设计清单，但不能称为“可订购产品”。

首批来源可以少；覆盖到的需求必须真实。例如“12 工位、6 座会议、1 电话亭”先能给出功能、尺寸和数量，再逐项找到符合场地的可售商品；未找到的显示待选品和继续搜索入口。已绑定商品须能说明规格、来源、能否放下、价格状态和替代选择。

## 不依赖客户测试的内部验收集

1. 可满足：18 × 12 m、两根柱，需求 12 工位、6 座会议、1 电话亭；设计清单数量正确，接入的已核实商品能形成至少一个无硬失败的可采购方案。
2. 面积不足：12 × 9 m，需求 40 工位、两间会议室；必须报工位/会议缺口，不得扩大场地。
3. 尺寸冲突：把桌换成大规格后碰到柱或使用净空；原规格可选，新规格拒绝或方案标待修复。
4. 目录缺货：停用唯一电话亭 SKU；设计清单保留电话亭需求，采购清单不得继续标为可订购，并给出待选品与替代候选（若有）。
5. 来源不足：AI 从商品页识别到电话亭图片和宣传尺寸，但没有供应商 SKU 或可靠供货信息；该候选只能待核实，不进入确定报价。
6. 预算取舍：改变预算后排序或缺口解释相应变化；不能删掉必需工位仍标需求满足。
7. 版本与账目：固定方案后改目录价格、删除/替换桌、切换 A/B/C；历史金额不变，新方案图、采购清单和金额一致。
8. 展示一致：三种不同尺寸场地使用同一渲染管线；精确商品图片里的可识别型号及主要家具数量与锁定布局一致；待选品只能显示通用占位。

已有 4F 与三个模拟矩形场地继续作为回归样本。每增加一种场地、家具类别或组合规则，先补正例、拒绝例和边界样本。样本通过只证明声明范围内的规则有效，不推断所有办公室都适用。

## 可实施性审查与首个代码切片

当前七项任务给出了方向和验收对象，但在工程开工前还要固定以下接口。现有页面由 studio.html 依次加载五个普通 JavaScript 文件，studio.js 与 broker.js 等脚本共享全局变量；package.json 尚无构建脚本。第一切片采用可同时被 Node 测试与浏览器动态 import 的纯 ESM 模块，保留现有页面加载方式，避免先重写整个编辑器。

### 切片 A：不接外部商品也能交付

1. 在 src/domain/product-slots.js 实现 buildProductSlots(displayItems)，输入当前 studio.js 的 allDisplayFurniture() 已展开的家具实例，生成稳定 slotId、类别、数量、位置、目标包络尺寸、使用净空与原实例 ID；不读取 samplePrice，也不把 DEMO SKU 写进功能位。之后再将派生家具展开逻辑从 studio.js 移入领域模块，避免同时重写旧逻辑。
2. 在 src/domain/design-bom.js 实现 buildDesignBom(slots)，按功能和规格归组，同时保留每个来源实例。项目家具拖动不改变数量，新增/删除应精确增减；导出后再导入结果相同。
3. 在 studio.js 的 renderStats() 下方接入“设计需求清单”和“采购商品状态”，先全部显示待选品。用动态 import 加载纯模块；加载或计算失败时保留现有演示清单并显示错误，不把空清单说成无需求。

出口：现有三个模拟场地中，设计清单的桌、椅、会议桌椅、电话亭数量与 allDisplayFurniture() 的实例对账；更改 A/B/C、增删家具、导出再导入后数量正确。4F 在旧数据转换器完成后加入回归。这个切片不依赖供应商或 AI 服务。

### 切片 B：结构化商品匹配

1. 定义 product-candidate.schema.json：sourceId、supplierSku、sourceUrl 或文件 ID、sourceTimestamp、类别、变体代码、尺寸毫米、价格及币种、供货状态、交期、各字段的来源证据、验证状态。把“规格已核实”“价格已核实”“供货已核实”拆成独立状态，不用一个 verified 布尔值概括。
2. 在 src/domain/catalog-import.js 接受供应商 CSV/JSON，输出标准化候选和逐行错误；用两份虚构供应商文件作固定测试资料。后续接入真实供应商时只加适配器，不改内部候选协议。
3. 在 src/domain/match-products.js 实现 matchProducts(slot, candidates)：先过滤类别、实物尺寸/使用净空、配置和摆位硬冲突，再根据预算、交期和风格排序，返回最多三个候选、拒绝原因与未匹配状态。匹配某真实尺寸后必须重新运行布局校核；若新尺寸使摆位失效，尝试重新排位或退回待选品，不能沿用演示块的通过结论。

出口：固定样本覆盖合适商品、大尺寸冲突、缺尺寸、缺价、停供和套装拆分；无证据的商品只显示候选，不能进入确定金额或可下单状态。

### 切片 C：AI 处理非结构化商品资料

供应商没有结构化文件时，服务端新增商品资料抽取接口，输入经允许取得的页面文本或文件内容，输出与 product-candidate.schema.json 一致的字段及原文证据；复用 api/extract-brief.js 的“服务端调用模型、严格结构化输出、再由代码校验”模式。AI 不能把没有出现的尺寸、SKU 或供货状态补成确定值。抽取结果先作为候选进入切片 B 的同一硬检查，不另建一套 AI 摆位或计价逻辑。

出口：固定资料中明确出现的字段能正确抽取并带出处；缺字段保持未知；同一商品不同来源冲突时显示冲突并禁止自动核价。

### 两个尚待外部输入的决定

- **商品来源**：至少一个可持续获取、允许使用的供应商商品文件或目录，以及商品更新责任人。没有它可以完成 A、B、C 的技术框架和固定样本，不能声称实际供应可购买。
- **报价与履约规则**：价格来源、运输/安装计费、税费、有效期、可下单地区及订单由谁接收。没有它可以形成选品清单，不能完成官网所述的正式报价和下单。

推荐系统的工程可行性由切片 A–C 验证；照片级可视化和订单仍是独立后续工程。完整产品计划只有在商品来源与报价规则明确后才具有可执行的对外交付日期。

- 调整搜索有次数上限，只提供已检查通过的选项；无建议表示当前已检查选项未通过，不能推断所有潜在商品和所有布局均不可行。真实目录继续暂缓，尚未建立多件协同替换、房间/共享区重排和正式报价能力。
