# 家庭户型识别验收

当前链路是：整图识别用途与内部锚点 → 按锚点放大提出墙线轮廓及矩形外接框 → 独立局部复核 → 对照已确认户型数量、墙线和重叠情况。轮廓和外接框都是 AI 草稿，外接框仍是家具计算所用的简化区域，不等于可测量的净室内面积；未核对完整边界前不绘制家具。无法定界的空间只显示红色锚点，需手工框选。

用 `test-data/home-plan-golden.json` 列出的七张用户图逐一测试。每张图在确认整套户型后点击“③ 分步识别空间”，随后点击“导出识别诊断”。诊断 JSON 不包含图纸、访问码或已批准家具位置。将七份诊断下载到本地后运行：

```powershell
node scripts/score-home-recognition.cjs path\to\diagnostic1.json path\to\diagnostic2.json
```

命令可以接收任意数量的诊断；缺少的样例会列为 `missing_diagnostic`。它比较有人工依据的卧室、客厅、卫生间数量，并筛查越界、重复锚点和明显重叠。浅色图 `1000276472.jpg` 的卫生间数量暂不计分，待清晰原图核实。3 室/4 室图用于检验“能识别但不使用不匹配套餐自动摆家具”。

## 边界草稿与正式评测

`test-data/home-plan-boundaries.json` 记录了七图的目测轮廓与功能区。它是**助手草稿，不是人工真值**：每张仍标为 `draft / partial`；封闭房间、开放式客餐厨、禁摆区与待判候选分开表示，不能把开放区强行称作有墙的房间。可先运行 `node scripts/render-home-boundary-overlays.cjs`，查看生成的 `local-projects/home-boundary-review.html`，对照原图核对多边形。

诊断评分现在报告每张草稿的临时召回和匹配 IoU，但草稿精确率与整体 `boundaryAccuracy` 均保持 `null`。尚未标注的空间不能算作 AI 误报；同样不能用草稿的高匹配率宣称已准确。导出的 `spaces` 是模型原始边界草稿，不等于通过产品安全门槛的可摆家具区域。

正式建立边界基准时，应由独立复核者逐张完成所有目标区域：墙内边界、开放式功能区的定义、阳台/露台/空调平台等禁摆区、门洞和不确定区。模糊图应换清晰原件，不能凭现有缩略图猜测。只有整张图覆盖完整并核对后，才把对应 `scope` 改为 `complete`、`reviewStatus` 改为 `reviewed`。评分器会拒绝将 `reviewed / partial` 当作有效真值。全部七张核对并取得真实模型诊断后，才生成整体边界 F1；仍须另测家具尺寸、净空和真实 SKU。这个本地评测不依赖 OpenAI Evals 平台。

数量全对也不代表边界准确。当前 `boundaryAccuracy` 仍为 `null`，还需对照原图人工核查每个框是否覆盖整个房间、有无跨墙/漏房。未完成真实模型七图回归前，不把此改动称为“识图已准确”。

## 七图空间清单与待判项

七张图的目测清单记录在 `test-data/home-plan-space-checklist.json`，多边形记录在 `test-data/home-plan-boundaries.json`。`1000276474.jpg`、`1000276473.jpg`、`1000276471.jpg`、`1000276470.jpg` 标为 `inventoryStatus: complete_draft`，表示可见空间已列成草稿；其余 `6476`、`6475`、`6472` 标为 `needs_source_review`，小卫浴/WC 候选仍是橙色待判区，必须换清晰原图或放大复核，不能凭套餐数量强行确认。任何 `complete_draft` 都不是独立人工真值，也不表示边界正确或模型通过验收。七张图始终维持 `reviewStatus: draft` 和 `scope: partial`。

先运行 `node scripts/render-home-boundary-overlays.cjs`，打开或刷新 `local-projects/home-boundary-review.html`，逐区检查是否漏标、重复、跨墙、超出套内，特别核对门洞、固定橱柜和通道。再运行：

```powershell
node scripts/audit-home-space-inventory.cjs
node scripts/audit-home-space-inventory.cjs path\to\6476-diagnostic.json path\to\6475-diagnostic.json path\to\other-diagnostics.json
```

第一条核对“草稿清单里的区域是否都已列出”、ID、类型、状态、锚点、多边形和待判原因；通过时 `auditPassed: true`，但 `draftChecklistsComplete` 仍为 `false`，因为三张图需要更清晰原件。第二条可接受任意数量真实诊断，并报告草稿区域中的锚点覆盖、漏检、重复及落入禁摆区或待判区的家具候选；待判区同样不得放家具，`needs_source_review` 的图不计算锚点覆盖率。诊断需来自用户实际上传图片后的“导出识别诊断”，不是上述目测标注。所有情况下 `formalAccuracy` 保持 `null`；这些检查只用于定位问题，不能宣传为识图准确率。

独立复核者应依据原始清晰图逐一修订所有空间及边界，确认待判区的用途与数量，再记录复核人、日期与版本；其后才能将相应图改成 `reviewed / complete`，并在七图回归中计算正式边界指标。待判图不应在界面上显示为“全空间已覆盖”。
