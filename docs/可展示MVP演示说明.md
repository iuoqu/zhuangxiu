# NBAI Space 可展示 MVP

状态：2026-10-22。当前 MVP 全程使用虚构场地、商品、价格和履约状态，展示从空间方案到商品组合、采购草案、报价、订单、安装与保修的交互。

## 演示入口与路径

1. 打开 `studio.html`，选择 **Try a quick demo**。
2. 选择任一模拟空间，进入布局 A / B / C。
3. 在右侧打开 **Products, packages & demo quote**。
4. 输入商品预算，点击 **Build product packages A / B / C**。
5. 比较 Value、Balanced、Style 三套完整商品组合并选择一套；二维和三维场景会立即切换整套材质。
6. 查看每件家具对应的示范 SKU；需要时可逐件换品，或点击 **Locate in plan** 定位到场景。
7. 点击 **Review placement & bind all**，对整个场景重新执行尺寸、使用空间、房间边界、固定物、家具碰撞和路线检查。
8. 审核通过后生成演示报价，依次确认报价并提交演示订单申请。重新生成报价会递增版本和编号。
9. 在同一订单上依次模拟确认、发出、送达、安装、验收。验收后展示从验收日起算的五年模拟保修期，并可登记及结案一条模拟售后请求。刷新后状态和记录仍在本地项目中。

固定的 40 人示例当前会展开为 56 件可采购实体，包括自动生成的椅子和房间内家具。布局占位本身不重复计入商品清单。

## 已完成能力

- 示范目录与真实目录适配器使用同一个规范化候选商品协议。
- 示范目录带固定目录版本、SKU、长宽高、价格、供货状态、交期、使用空间证据和三个饰面层级。
- 明确覆盖衣橱、桌、椅子、梳妆台、沙发、茶几、矮柜和床，同时覆盖当前办公室布局中的会议桌、办公桌、电话亭、柜、架、设备等用途角色。
- 自动为全部家具实例生成三套方案：经济型、均衡型和风格型。
- 品类、用途角色、商品证据和可放置尺寸属于硬条件；找不到候选时保留明确缺口。
- 用户选择整套方案后仍可逐件替换；最终保存前执行完整场景复核。
- 每个 SKU 带版本化视觉参数；类别几何模板与商品颜色、材质、饰面分开，因此不需要穷举制作每件商品模型。
- 商品尺寸写回同一布局对象，二维、商品材质三维、设计清单和采购草案读取同一批家具实例。
- A / B / C 和逐件换品会立即改变场景；清单可定位场景家具，画布选择也会标出对应商品行。
- 演示报价固定布局版本、目录版本和采购明细；布局、商品或价格发生变化后旧报价显示为过期。
- 报价包含商品、配送估算、安装估算、税费估算、总价、编号、版本和有效期。
- 报价确认后可以生成演示订单申请；订单保存对应报价的布局、目录、商品行和金额快照。状态按申请、确认、发出、送达、安装、验收顺序人工推进。
- 验收后才启动五年模拟保修；模拟售后请求可登记和结案。方案或商品变化使旧报价失效，不能继续推进旧订单；此前的演示报价和订单保留在只读历史中（最多八组）。
- 项目、商品组合预览、自定义选择、商品绑定、报价、订单和售后记录保存在浏览器本地，刷新后可恢复。

## 数据边界

所有 `demo-catalog://` 商品、供货状态、交期和金额均为虚构演示数据。配送、安装、验收和保修记录也只在当前浏览器中模拟，不会创建实际付款、采购、物流、服务合同或保修权益。界面持续显示演示标记。

接入真实目录时替换目录适配器并重新执行现有证据、摆位和报价检查；布局、选品组合、清单和报价状态结构无需重写。

## 自动验证

- 领域测试验证八类家具、三个价格层级、版本化商品视觉、完整场景自动填充、套餐差异、报价版本绑定、订单状态顺序和五年模拟保修。
- 浏览器测试 `showcase-mvp.browser.test.cjs` 验证 56 件家具、三套场景材质即时切换、商品定位、报价版本、订单至售后状态和刷新恢复。
- 原客户流程浏览器测试继续覆盖布局 A / B / C、混合场景商品绑定、布局调整、快照、家居家具和办公家具回归。
